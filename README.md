## Reproduce

All analysis code lives in the `analysis` package (`src/analysis/`). The
publication notebook (`index.ipynb`) loads a generated dataset and pre-trained
checkpoints; the steps below regenerate those inputs from scratch. See also
[SETUP.qmd](pages/SETUP.qmd).

### 1. Set up the environment

```bash
conda env create -n world-model-orbits --file env.yml
conda activate world-model-orbits
pip install -e .          # makes the `analysis` package importable
```

### 2. Generate the dataset

Writes 20,000 Kepler trajectories (10k train + 10k test) to `data_cv/`:

```bash
python -m analysis.data_generation
```

### 3. Train the models

Trains the three models the analyses depend on and writes them to
`checkpoints/kepler_cv_blocksize_elm/`:

| block_size | noise_scale | role |
|---|---|---|
| 2   | 0.1 | noisy short-context (rotation heuristic) |
| 100 | 0.1 | noisy long-context (Keplerian) |
| 2   | 0.0 | noiseless short-context (Verlet + Newtonian gravity) |

```bash
python -m analysis.training           # full run (~20k steps/model, GPU recommended)
python -m analysis.training --smoke   # fast sanity check (200 steps, not for publication)
```

### 4. Run the analyses

With `data_cv/` and `checkpoints/` in place, execute `index.ipynb` (e.g. in
Jupyter, or `quarto preview` for a live render of the publication).

> **Notes.** Run steps 2–3 from the repository root so `data_cv/` and
> `checkpoints/` resolve correctly. Both directories are untracked in git
> (regenerated by steps 2–3). Because of GPU nondeterminism, reproduced
> checkpoints are scientifically equivalent to the originals, not byte-identical.
